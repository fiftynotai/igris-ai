fifty.devsystem architecture walkthrough
// WHAT IGRIS IS

Three things, one system

  1. 01A multi-agent team — an orchestrator that delegates to specialists, behind quality gates.
  2. 02A persistent brain — memory, briefs, and decisions that survive across sessions and projects.
  3. 03A harness-agnostic OS — the same system runs on Claude, Codex, Gemini, OpenCode, Antigravity.
The model is the CPU. Igris is the operating system that runs on it.
// THE MENTAL MODEL

Model is the CPU. Igris is the OS.

Model=CPUraw reasoning — swappable, harness-agnostic
Igris=OSthe layers, contracts & mechanisms it runs
/boot=bootloaderthe ceremony that loads the OS into the model
project=mounted volumeper-project context, mounted at session start
Boot is project-independent. Mount is per-project. Never conflate the two.

Hand-maintained registries are the disease — they drift the moment code changes. Parts declare their metadata; the OS discovers them and generates the index. Growth = "which layer?" → drop it in.

v7 retired a 46KB monolith + a hand-encoded routing tree for exactly this.

// CAPABILITY · THE GUARDRAILS

Why it stays honest

brief-firstno file modification without an active brief
phase-guardno commit out of workflow phase
consumer-sweepchange a contract → every consumer re-pointed, same commit
enforcementdetectable violations gated by hooks + a registry
delegationspecialists run behind plan → test → review

The disciplines live as conduct (always-followed) and as mechanism (hooks that gate what's detectable). Convention where it must persuade; enforcement where it can be checked.
