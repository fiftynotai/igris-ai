# Multi-CLI Skill Distribution

**Brief:** FR-103
**Status:** Stable
**Last Updated:** 2026-04-20

Igris skills live canonically under `~/.igris/core/skills/`. This document defines how
those skills are distributed to multiple CLI agents (Claude Code, OpenCode, Gemini CLI,
Codex CLI) via filesystem routing — no duplication, no drift.

---

## Supported CLIs

| CLI | Method | Target | Notes |
|-----|--------|--------|-------|
| Claude Code | `symlink` | `~/.claude/skills/` | Each `~/.igris/core/skills/{name}/` becomes a symlink at `~/.claude/skills/{name}/`. Full directory linked so nested assets (`scripts/`, `workflow-template.md`, `templates/*.md`) are available. |
| OpenCode | `none` | `~/.config/opencode/` | No-op. OpenCode reads `~/.claude/skills/` natively as a fallback; the Claude-side symlinks cover it. Flip `method: "symlink"` in `~/.igris/config.json` if a future OpenCode version stops falling back. |
| Gemini CLI | `converter` | `~/.gemini/commands/` | Per-skill TOML files generated by `md_to_gemini_toml.sh`. Each `{name}/SKILL.md` produces one `{name}.toml` containing `description` and `prompt` keys only. |
| Codex CLI | `compiler` | `./AGENTS.md` | All non-Claude-only skills concatenated into a single `AGENTS.md` at the project root being installed to. 32KB cap enforced; skipped skills logged loudly. |

---

## Configuration

`~/.igris/config.json` has a top-level `cli_targets` block controlling distribution:

```json
{
  "cli_targets": {
    "claude":   { "method": "symlink",   "target": "~/.claude/skills/" },
    "opencode": { "method": "none",      "target": "~/.config/opencode/" },
    "gemini":   { "method": "converter", "target": "~/.gemini/commands/", "converter": "scripts/cli-adapters/md_to_gemini_toml.sh" },
    "codex":    { "method": "compiler",  "target": "./AGENTS.md",         "compiler":  "scripts/cli-adapters/md_to_agents_md.sh" }
  }
}
```

Each entry supports:
- `method` — one of `symlink`, `converter`, `compiler`, `none`
- `target` — output path (tilde-expanded, relative paths resolve from project root at sync time)
- `converter` / `compiler` — path (relative to repo) of the adapter script
- `note` — human-readable intent, for maintainers

## Portability Convention

Skills are authored for Claude Code first. To mark CLI-specific frontmatter, use the
optional `platform_overrides` block:

```yaml
---
name: scan
description: Show system status report
disable-model-invocation: false
platform_overrides:
  claude:
    allowed-tools:
      - Read
      - Grep
      - Glob
      - Bash
      - mcp__igris-brain__igris_project_status
    triggers:
      - "SCAN"
      - "REPORT"
  codex:
    include: false   # opt-out from AGENTS.md aggregation
---
```

### Frontmatter Handling Per CLI

| CLI | Behavior |
|-----|----------|
| Claude | Full frontmatter preserved (all keys including `platform_overrides.claude`). |
| Gemini | Only `description` is extracted — used for the TOML `description` key. Everything else is stripped. |
| Codex | Entire frontmatter is stripped. Body-only concatenation under a `# {name}` header. |

### Flat Frontmatter (Current Default)

Existing skills use flat Claude-specific keys (`allowed-tools`, `triggers`,
`disable-model-invocation`) at the top level. Adapters continue to tolerate flat
frontmatter as a fallback — migration to `platform_overrides` is **optional**, not
required.

## Claude-Only Skill Detection

The Codex compiler excludes skills that are Claude-only. A skill is considered
Claude-only if **either** signal is present:

1. `platform_overrides.codex.include: false` in frontmatter (explicit opt-out).
2. The body contains `Agent(...)` or `Skill(...)` invocation patterns — a heuristic for
   orchestration skills that assume Claude's subagent API.

Excluded skills are logged to stderr and listed in a trailing `<!-- -->` comment inside
the generated `AGENTS.md`.

---

## Nested Skill Files

Converters (`md_to_gemini_toml.sh`) and the compiler (`md_to_agents_md.sh`) read
**exactly one** input per skill: the top-level `SKILL.md`. Nested files like
`scripts/*.sh`, `workflow-template.md`, and `register/templates/*.md` stay Claude-only.
Claude still receives the full directory symlink, so it sees every nested asset.

If you author a skill that references nested content, expect that content to be invisible
to Gemini/Codex consumers. Inline the critical parts into `SKILL.md` body or accept the
portability trade-off.

---

## 32KB Cap (Codex)

`AGENTS.md` is subject to a 32KB (32768 byte) limit. The compiler:

1. Sorts skills alphabetically for deterministic output.
2. Streams bodies one at a time, tracking running byte count.
3. If adding the next skill body would exceed 32KB, skips it with a loud stderr warning:
   `Skipped {name}: would exceed 32KB cap`.
4. Emits a trailing summary comment: `<!-- Generated by igris_cli_sync.sh on YYYY-MM-DD -- N included, M skipped -->`.

## How to Add a New CLI Adapter

1. Pick a method: `symlink`, `converter`, `compiler`, or `none`.
2. Add an entry to `cli_targets` in `~/.igris/config.json`.
3. If `converter`/`compiler`: drop a script under `scripts/cli-adapters/` implementing
   the contract:
   - **Converter:** `adapter.sh <input-skill-md> <output-path>` — one skill → one output.
   - **Compiler:** `adapter.sh <output-path>` — all skills → one output.
4. Source `scripts/cli-adapters/_common.sh` for shared helpers
   (`parse_frontmatter`, `strip_frontmatter`, `is_claude_only`, `toml_escape`).
5. Add a test case in `test/igris_cli_sync.test.bash` exercising the new adapter with
   a fixture.

---

## Invocation

- **Install-time:** `bash scripts/igris_install.sh --cli=claude,gemini,codex <project-dir>`
- **Runtime refresh:** `bash scripts/igris_cli_sync.sh --cli=all` (called automatically by
  `/awaken` step 3.6.3.a after `igris_definition_pull` reports updates)

`--cli=all` expands to every entry in `cli_targets` (including `none` entries, which are
silent no-ops).
